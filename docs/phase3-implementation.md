## 1. The correctness item — one denominator, two worlds

Phase 1 fixed *which subjects* `/ranking` and the report engine average over. It recorded, and
deliberately deferred, the other half: *which columns*. This closes it.

### The defect

There are two curriculum worlds, and the denominator differs between them:

| World | Denominator |
| --- | --- |
| **level curriculum** — the class resolves rows tagged with its level (00021/00026/00028: every real class on a migrated database) | the resolved, selection-narrowed curriculum |
| **untagged fallback** — a pre-V2 account with no class, or a database where the seeds have not run | `FALLBACK_NUMERIC_KEYS`: the 29 monthly / 13 semester columns this app has always counted |

`resolveTemplate` on the untagged path yields only 00016's fourteen rows — **16** numeric
monthly columns, not 29. The screens gated on `levelCurriculum` and used the legacy list;
`resolveMonthlyClass` did not. So a legacy class was averaged over sixteen columns on paper and
twenty-nine on screen, and every `sci_*`, `soc_*`, `pe_sport`, `health_hygiene`, `life_skill`
and `foreign` mark was silently dropped from the printed sheet.

**Two more asymmetries surfaced while fixing it**, both the same shape — the engine derived from
`context.levelKey` what the screens derived from what actually *resolved*:

- **the grading scheme.** A class whose level is set but whose curriculum has no seeded rows was
  graded **/50** by the engine and **/10** by the screens. A whole different scale, same pupils.
- **the template fallback.** The engine passed raw `templateRows` to `resolveTemplate` with no
  `SYSTEM_PRIMARY_TEMPLATE` fallback, so on a database where the seeds have not run it resolved
  **zero** subjects and every report printed a blank sheet while the screens rendered normally.

### The fix — the rule written once

[`periodDenominator(mode, subjects, levelCurriculum)`](../lib/scores/aggregate.ts), in the layer
that already owns both halves (`numericColumnKeys` and `FALLBACK_NUMERIC_KEYS`):

```ts
return levelCurriculum ? numericColumnKeys(subjects) : FALLBACK_NUMERIC_KEYS[mode]
```

`/ranking` and `resolveMonthlyClass` both call it. The engine also now computes
`levelCurriculum = usesLevelCurriculum(source, context)` and uses it for the scheme, and falls
back to `SYSTEM_PRIMARY_TEMPLATE` like every other surface.

**The property the harness pins is not that both call it** — it is that **neither may express
the gate itself**. A second copy of a two-world rule is how the worlds come to disagree again,
so `verify-score-workspace.mts` §7 asserts that neither `RankingClient.tsx` nor
`report-data.ts` mentions `FALLBACK_NUMERIC_KEYS` or `numericColumnKeys` at all, and that
`aggregate.ts` still carries the conditional.

`ReportPayload.numericKeys` became `readonly string[]`: `periodDenominator` may hand back the
shared `FALLBACK_NUMERIC_KEYS` constant itself, and a caller that sorted or spliced it would
corrupt the denominator for every other surface in the process.

**Behaviour change, stated plainly.** Reports generated by a legacy or unseeded account now
count the columns the screens count. For every class on a migrated database — which is every
real class — nothing moves.

## 2. `/score-analyse` and `/score-analysis/subject` were one screen

Two routes one character apart, sitting as sibling entries in the same menu. Nothing on either
told a teacher which one they had opened, and the pair read as a typo rather than as an
information architecture. They also answer the same question: *how is this class doing*, read
across the pupil and read across the subject.

They are two **views** now:

```
វិភាគទិន្នន័យសិស្ស        /score-analyse
  [ ទិដ្ឋភាពរួម ] [ តាមមុខវិជ្ជា ]
```

`SubjectAnalysisClient.tsx` → `score-analyse/SubjectAnalysisView.tsx`: **the same component**,
moved and renamed. Not one chart, query or figure changed — it lost its own `PageContainer` and
`PageHeader` (it renders inside its host's now) and nothing else. Only the active view is
mounted, because each fetches its own marks and rendering both would double every request to
serve one of them.

The view lives in local state, not `?view=`: the tab declares `carriesPeriod: false` and reads
no search param, and adding one would make the address bar claim something
`verify-score-workspace.mts` §3 checks it does not.

`/score-analysis/subject` is now a redirect preserving `?class=`, declared `hidden: true` — the
same pattern `/score/template` and `/classroom/classes` use, so no bookmark 404s and the
breadcrumb names a module mid-redirect rather than blanking.

## 3. The fifth workspace tab

```
បញ្ចូលពិន្ទុ · តារាងសរុប · ការប្រមូលពិន្ទុ · ចំណាត់ថ្នាក់ · វិភាគ
```

`/score/collect` was `hidden: true` under ពិន្ទុ — reachable only from the dashboard's progress
tile. "How much of this period is still unmarked" is the question a teacher asks *between*
entering and reading, and `lib/scores/completion.ts` already guarantees it and the dashboard
report the same figure.

**Both new tab destinations now wear the strip.** `/score/collect` and `/score-analyse` were tab
targets while showing a plain `PageHeader` — a tab that lands somewhere with no strip is a
one-way door. Both use `ScoreWorkspaceHeader` now, which states class · grade · year, so neither
needs a separate `ClassContextBar`.

`/score/print` is deliberately **not** a tab: it is a document, and documents are indexed in the
Print Center. A strip mixing screens and sheets would be the competing document menu that index
exists to replace.

## 4. លទ្ធផល is a module

The RESULTS step of the teacher's journey had no representation in navigation. Three of its four
screens were `hidden: true` children of ពិន្ទុ or របាយការណ៍, reachable from a card or another
screen and from no menu, while ពិន្ទុ carried nine children — four of them invisible.

```
ការវាយតម្លៃ
  ពិន្ទុ      /score/enter   · បញ្ចូលពិន្ទុ · តារាងពិន្ទុសរុប · មុខវិជ្ជាតាមថ្នាក់
  លទ្ធផល ★    /ranking       · តារាងចំណាត់ថ្នាក់ · ការប្រមូលពិន្ទុ · វិភាគទិន្នន័យ · តារាងកិត្តិយស
  កិច្ចការផ្ទះ /homework/enter · បញ្ចូលពិន្ទុកិច្ចការផ្ទះ · បញ្ជូនទៅអាណាព្យាបាល
  របាយការណ៍   /print-center  · មជ្ឈមណ្ឌលរបាយការណ៍
```

**No route moved.** Every URL is the one that existed before.

Three decisions worth recording:

**ពិន្ទុ opens on `/score/enter`, not `/score/total`.** The module lands where the *work* is
done. It is the same correction វត្តមាន already had — its front door was moved off the
read-only monthly sheet onto the register.

**`/score/total` stays in ពិន្ទុ.** It reads as a result, but its twenty-nine-column matrix is
**editable**, one toggle from the results table, so it is still a marking surface.

**The tab strip spans both modules, and that is not a contradiction.** The strip is the
*within-task* navigation of one job spread over five screens; the rail is the information
architecture. A teacher moving between the five never leaves the strip; a teacher looking for
"how did they do" now has somewhere to click. `verify-navigation.mts` asserts **no href is
claimed by two modules** — two `PATH_INDEX` entries for one path would make the sidebar
highlight whichever the longest-match sort reached first.

## 5. A Phase 0 assumption that was already wrong

Phase 0 §10 question 2 proposed converging `/honor-roll`'s "top 5" onto the report's
`evaluateHonor` criterion, with the assumption *"converge in Phase 3; a podium is a layout, not
a policy."*

**It was already converged.** `HonorRollClient` imports `evaluateHonor`, `defaultHonorCriteria`
and `HONOR_CRITERIA_PROVENANCE`, decides eligibility against the class's own grading scheme, and
lists everyone who qualified beyond the podium's five in `alsoEligible` —
`verify-score-workspace.mts` §6 has asserted all of that since before Phase 1. The Phase 0
finding was drawn from a stale paragraph in CLAUDE.md's *Reporting* section, which still
describes the pre-convergence behaviour while its *Results* section describes the current one.

Nothing was changed for it. `/honor-roll` did move from `hidden` under របាយការណ៍ to a visible
entry under លទ្ធផល, which is an IA change, not a behaviour one.

**CLAUDE.md's Reporting section should be corrected** — it is the source of a finding that cost
this phase an investigation. Left for the documentation pass rather than edited here, since
CLAUDE.md is the project's own record and not this program's to rewrite mid-phase.
